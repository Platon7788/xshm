# Изменения

## 1.1.0 — 2026-10-19

Добавлены методы submit_*_owned у ClientSender и DispatchSender. Готовый
Vec передаётся worker без копирования payload; при отказе постановки
OwnedSendError возвращает исходный буфер для повторной попытки. Лимит
очереди учитывает capacity owned-буфера, включая неиспользованный запас.
После принятия ошибки исполнения по-прежнему сообщает CommandCompletion;
буфер после принятия не возвращается. Методы для &[u8] сохраняются.

prof-shm передаёт сериализованные сообщения новым API и повторно использует
возвращённый буфер при backpressure. C-протокол, ABI и режимы вытеснения
не менялись. Это убирает одну копию payload и отдельный Vec для очереди,
но не копирование в/из разделяемой памяти.

## 1.0.0 — 2026-10-19

Единственный транспорт — C-ядро xipc 2.2+ из xhook/ipc. Rust-реализация
протокола полностью удалена. Поддерживаются Windows MSVC x86/x64.

Несовместимое изменение публичного API:

| Прежний API | API 1.0 |
|---|---|
| SharedServer / SharedClient | Server + borrowed Session / Client |
| Auto*, фоновые Multi/Dispatch traits | ClientWorker / DispatchWorker и FnMut callbacks; MultiServer event loop |
| ChannelLayout, builder RingConfig | Layout / RingConfig со значениями полей, ChannelConfig::default |
| ObjectSecurity / ShmError | Security / Error |
| recv_async и заимствования буфера кольца | receive_into + wait_readable / wait_activity |
| Неявные таймауты | Wait и ConnectBudget |
| u32 как адресат отправки | MultiPeer / DispatchPeer с проверяемой идентичностью |
| Отправка в очередь считалась отправкой | CommandCompletion с результатом C-операции |
| xshm::c_core, feature c-core | Обычный xshm без feature |

Rust не хранит копию раскладок внутренних C-объектов. C выделяет и освобождает
opaque owners; namespace и descriptor живут достаточно долго. Приём копирует
данные и не выдаёт ссылки на память, которую меняет другой процесс.
Фоновые очереди ограничены по числу команд и байтам; lossless-ожидание места
не останавливает чтение встречного направления. Хук профайлера наследуется
рабочими потоками. Остановка ждёт callbacks и возвращает сохранённую ошибку.

Поставка: XIPC_SOURCE_DIR либо XIPC_SDK_PREFIX, без автоматического fallback.
Проверяются ABI, архитектура и CRT. Wire-формат C остаётся `0x00020000`,
рукопожатие — ревизия 3; прикладной протокол prof-shm не меняется.
История прежних выпусков доступна в Git.

Регрессия завершения: закрытие TX не публикует закрытую очередь до callback
последнего входящего кадра. Иначе prof-shm мог потерять BYE отказа и повторить
регистрацию. Управляемый тест порядка callbacks падает до исправления;
проверка отказа prof-shm x86 Release дополнительно повторена 25 раз.
