# xshm 1.0

Безопасный Rust API над единственным C-ядром xipc 2.2+ из `xhook/ipc`.
C/C++, Rust и prof-shm используют одну реализацию транспорта.

Самостоятельные Rust-кольца, NT API, рукопожатие, реактор и Auto API удалены.
Временных feature, переходного модуля и запасной реализации нет.

## Сборка

Windows MSVC x86/x64, Rust 1.99+, CMake 4 и инструменты MSVC C/C++.
Выберите один источник C-библиотеки:

```powershell
$env:XIPC_SOURCE_DIR = 'D:/GitHub/VsProjects/xhook/ipc'
cargo test --workspace -- --test-threads=1
```

Либо задайте `XIPC_SDK_PREFIX` на установленный hosted Release SDK xipc 2.2+,
убрав `XIPC_SOURCE_DIR`. Архитектура и CRT SDK должны совпадать с Rust.
Репозиторий настроен на статический CRT. Неверный ABI, CRT или SDK — ошибка
сборки. Исходники C не копируются в Rust-проект.

Публичный API находится непосредственно в `xshm`: `Server`, `Session`,
`Client`, `MultiServer`, `DispatchServer`, `DispatchWorker`, `ClientWorker`.
Синхронный приём копирует данные в буфер вызывающего. Соединение имеет
одного владельца; сессия заимствует сервер исключительно. Идентичность
пиров защищена от повторного использования слотов/номеров сессий.

Очереди фоновых потоков ограничены. `CommandCompletion` подтверждает
исполнение C-операции, но не чтение пиром. `stop` отменяет оставшиеся команды
и ждёт поток. Таймаут ожидания подтверждения или его Drop команду не отменяет.
Из обработчика нельзя синхронно ждать собственный рабочий поток.

Маяки, пространства имён, политики безопасности, ожидания процессов и отмена
также используют C-ядро. PID не является аутентификацией. С `panic=abort`
паника завершает процесс; перехват паники возможен только при `panic=unwind`.
